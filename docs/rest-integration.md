# REST Integration

`ZeroAlloc.Rest` consumes serializers through its own `IRestSerializer` contract, not
`ISerializer<T>` directly. This page covers Rest 3.0 and later.

> **On Rest 2.x?** Rest 2.x ships `RestSerializerAdapter<T>`, a built-in bridge from
> `ISerializer<T>` to `IRestSerializer`. It still works there; keep using it until you upgrade.
> Rest 3.0 removed the class — see its
> [migration guide](https://github.com/ZeroAlloc-Net/ZeroAlloc.Rest/blob/main/docs/migrating-to-v3.md#restserializeradaptert-is-removed).

## Recommended: SystemTextJsonSerializer for JSON

For JSON clients, the recommended route is Rest's own `SystemTextJsonSerializer` backed by a
`JsonSerializerContext`, from the `ZeroAlloc.Rest.SystemTextJson` package. It needs no bridge to
`ZeroAlloc.Serialisation` and is AOT-safe, because the source-generated context resolves every
type ahead of time instead of through reflection:

```bash
dotnet add package ZeroAlloc.Rest.SystemTextJson
```

```csharp
[JsonSerializable(typeof(OrderCreated))]
internal partial class MyApiJsonContext : JsonSerializerContext
{
}

services.AddSingleton<IRestSerializer>(new SystemTextJsonSerializer(MyApiJsonContext.Default));
```

Prefer this over bridging `ISerializer<T>` whenever the backend format is JSON.

## Bridging an `ISerializer<T>`

For a non-JSON backend, such as MemoryPack or MessagePack, where you already have an
`ISerializer<T>` from `ZeroAlloc.Serialisation`, write a short adapter. `RestSerializerAdapter<T>`
no longer ships with Rest 3.0, so this is the same adapter Rest's own migration guide hands you:

```bash
dotnet add package ZeroAlloc.Rest
dotnet add package ZeroAlloc.Serialisation
dotnet add package ZeroAlloc.Serialisation.MemoryPack  # or your chosen backend
```

```csharp
using System.Buffers;
using ZeroAlloc.Serialisation;

public sealed class MyAdapter<T>(ISerializer<T> serializer) : IRestSerializer
{
    public string ContentType => "application/octet-stream";

    public async ValueTask<TResult?> DeserializeAsync<TResult>(Stream stream, CancellationToken ct = default)
    {
        if (typeof(TResult) != typeof(T))
            throw new InvalidOperationException($"{nameof(MyAdapter<T>)} can only deserialize {typeof(T).Name}, not {typeof(TResult).Name}.");

        using var ms = new MemoryStream();
        await stream.CopyToAsync(ms, ct);
        return (TResult?)(object?)serializer.Deserialize(ms.GetBuffer().AsSpan(0, (int)ms.Length));
    }

    public async ValueTask SerializeAsync<TValue>(Stream stream, TValue value, CancellationToken ct = default)
    {
        if (value is not T typed)
            throw new InvalidOperationException($"{nameof(MyAdapter<T>)} can only serialize {typeof(T).Name}, not {typeof(TValue).Name}.");

        var buffer = new ArrayBufferWriter<byte>();
        serializer.Serialize(buffer, typed);
        await stream.WriteAsync(buffer.WrittenMemory, ct);
    }
}
```

```csharp
// Register the ISerializer<T> for your type
services.AddOrderCreatedSerializer();  // generated by ZeroAlloc.Serialisation.Generator

// Bridge it to IRestSerializer
services.AddSingleton<IRestSerializer>(sp =>
    new MyAdapter<OrderCreated>(sp.GetRequiredService<ISerializer<OrderCreated>>()));
```

Set `ContentType` to match the backend format (e.g. `application/x-memorypack`,
`application/x-msgpack`). The adapter is a thin bridge — `IRestSerializer` and `ISerializer<T>`
remain independent contracts; it rents an `ArrayBufferWriter<byte>` and writes `WrittenMemory` to
the stream, so serializing does not allocate an intermediate `byte[]`.
